# ORB-SLAM3 Performance Evaluation (MONO) with EVO

This document explains how to evaluate ORB-SLAM3 trajectory accuracy
using the EVO toolkit. It is designed for the SJTU ROS2 setup where you
play a rosbag2 and run ORB-SLAM3 (MONO) in Docker.

Workflow: 1. Export Ground Truth and SLAM trajectories from the rosbag
into TUM format 2. Visualize trajectories with alignment 3. Compute ATE
(Absolute Trajectory Error) and RPE (Relative Pose Error)

------------------------------------------------------------------------

## Requirements

-   ROS2 Humble (or compatible)
-   ORB-SLAM3 ROS2 wrapper publishing:
    -   /robot/robot_pose_slam
-   Ground truth topic:
    -   /simple_drone/gt_pose
-   EVO installed: pip install evo --upgrade
-   Export script: bag2_to_tum_ros2.py

------------------------------------------------------------------------

## TUM Format

timestamp tx ty tz qx qy qz qw

-   timestamp in seconds
-   translation in meters (or simulation units)
-   quaternion (qx, qy, qz, qw)

------------------------------------------------------------------------

## 1) Run SLAM + Play Bag

Play bag: ros2 bag play rosbag2_2026_03_01-15_16_56 --clock --rate 0.5

Run ORB-SLAM3 MONO inside Docker: ros2 launch orb_slam3_ros2_wrapper
mono_sjtu.launch.py use_sim_time:=false

Ensure ROS_DOMAIN_ID and RMW implementation match across host and
container.

------------------------------------------------------------------------

## 2) Export Trajectories from rosbag2

source /opt/ros/humble/setup.bash

python3 bag2_to_tum_ros2.py rosbag2_2026_03_01-15_16_56
/simple_drone/gt_pose gt_tum.txt python3 bag2_to_tum_ros2.py
rosbag2_2026_03_01-15_16_56 /robot/robot_pose_slam slam_tum.txt

Validate: wc -l gt_tum.txt slam_tum.txt head -n 3 gt_tum.txt

------------------------------------------------------------------------

## 3) Visualize Trajectories

For MONO, scale alignment is mandatory:

evo_traj tum gt_tum.txt slam_tum.txt --ref gt_tum.txt -as -p
--plot_mode=xz

Flags: --ref gt_tum.txt : reference trajectory -a : rigid alignment -s :
scale alignment (required for MONO) -p : plot --plot_mode=xz : top-down
view

------------------------------------------------------------------------

## 4) Compute ATE

evo_ape tum gt_tum.txt slam_tum.txt -as -p

ATE measures global trajectory accuracy.

Key metric: RMSE

------------------------------------------------------------------------

## 5) Compute RPE

evo_rpe tum gt_tum.txt slam_tum.txt -as -p

RPE measures local drift and short-term consistency.

------------------------------------------------------------------------

## Troubleshooting

If you see: \[ERROR\] Can't align or sync without a reference!

Use: evo_traj tum gt_tum.txt slam_tum.txt --ref gt_tum.txt -as -p

If timestamps mismatch: evo_ape tum gt_tum.txt slam_tum.txt -as -p
--t_max_diff 0.02

Increase gradually if needed.

------------------------------------------------------------------------

## Recommended Benchmarking

To compare MONO vs RGB-D:

1.  Run each mode 3 times
2.  Export TUM files
3.  Compare ATE RMSE
4.  Compare RPE statistics
5.  Analyze consistency across runs

------------------------------------------------------------------------

ORB-SLAM3 does not publish occupancy grids directly. It publishes poses
and map points. Occupancy grids are generated by a separate node.
